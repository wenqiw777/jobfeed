# JD 语义解析设计：事实、关系与决策分离

日期：2026-09-04。状态：供讨论的设计，尚未实现或通过准确率验收。

## 目标与边界

统一提取 graduation / enrollment / start date、YOE、degree、compensation、岗位级别和技能要求，为 eligibility、Career Stage Fit、Compensation、Evidence Fit 提供事实。公司强度使用独立的有来源公司数据，不从 JD 宣传文案推断。

本次只写设计，不改生产代码、评分权重、数据库、现有实验或部署。保留 docs/job-search-policy.md 已确认的评分政策；本设计不是恢复旧 stage A/B。所有测试、恢复和 fallback 均遵守项目 AGENTS.md 的禁用约定。

## 经验来源及适用范围

- LinkedIn 的技能抽取：结构识别、词典和 BERT 语义候选、上下文关系分类、标准化及用户反馈。借鉴上下文和关系建模，不把技能模型误称为学历或薪资解析器。https://www.linkedin.com/blog/engineering/skills-graph/extracting-skills-from-content
- Amazon / NASWA 的 JD 研究：HTML 正文经轻量清理后，使用固定指令让基础模型返回 JSON。借鉴完整文本结构化抽取，不把统计分布验证当成逐条资格判定准确率。https://creddy.net/papers/DGOV25.pdf
- Affinda JD Parser：保留 raw、parsed、字段位置和置信信息。借鉴可追溯事实输出，不把模型 confidence 当已校准正确率。https://docs.affinda.com/resumes/job-description-parser
- AnyParser：文档版面和多模态抽取。仅在 PDF、图片、版面复杂材料需要时采用同类能力；普通 HTML 不必先截图再 OCR。Jobright 的客户背书只涉及简历解析，不能证明它的 JD 管线。https://www.cambioml.com/research/AnyParser_Epsilla_Whitepaper.pdf

这是综合这些经验提出的 Jobfeed 设计，不是任何一家公司的完整内部实现复刻。

## 数据流

来源文档 → 保留原生结构的统一文档 → 语义事实抽取 → 验证及必要升级 → 确定性资格判断 → 独立评分

### 1. 统一文档，不先用 regex 截断证据

按实际能力读取官方 API、嵌入 JSON、JobPosting JSON-LD、HTML 或渲染 DOM。保留 URL、已有岗位 ID、获取时间、完整正文、标题、段落与列表层级、原生字段和正文位置。非 ATS 同样处理，第三方副本注明来源。

每个文档记录完整性：complete / partial / unavailable。complete 代表通过预定义的正文、分页、加载和截断检查，不是保证网站提供了所有信息。加载失败或正文截断不能产生 not_stated。

原生 salary 字段先直接解析类型和单位，但不是绝对真相：核对职位、地点、币种和正文；冲突时保留双方证据并升级，不能静默覆盖。结构识别只提供上下文，不删除公司介绍或强制限定模型只能看某一段。

### 2. 两个抽取任务，共享全文

资格解析器联合读取 degree、YOE、graduation、enrollment、start date、岗位级别、技能及条件关系。薪资解析器独立处理金额、币种、周期、base/bonus/equity/OTE/TC、地点和适用人群。它们是两个输出任务，不要求部署两套不同模型权重。

初版使用可配置的低成本 LLM，固定输出 schema；不先训练 BERT，不以 regex 决定哪些句子允许进入模型。字段类型校验和已明确语义后的数字、单位转换由代码完成。任何模型返回的 JD 内指令一律作为数据，不执行。

### 3. 事实合同：数值与关系同样重要

所有字段保存状态、原文证据、块位置、主体、required/preferred/negated 性质、适用范围、解析版本。状态为 present / not_stated / ambiguous / conflicting / unavailable。模型自报 confidence 仅供诊断，不直接决定自动放行。

资格条件用显式 all_of / any_of 树，叶节点引用事实 ID，不使用无法追踪关系的自由文本分组名。例如：

```text
required:
  any_of:
    all_of: Bachelor; professional_experience >= 5 years
    all_of: Master; professional_experience >= 3 years
preferred:
  distributed_systems_experience
```

YOE 保存比较符、上下限、领域、是否排除实习、是否要求毕业后经验。more than 5 是 >5，不能改成 >=5；Proven experience 可以 required，但数值下限未知。学历未指定层级时不强行归一为 Master 或 Bachelor。

毕业、开工、申请截止日期使用不同类型；公司成立年份不是候选人毕业条件。Salary 是多条适用范围记录，不能把纽约范围和加拿大范围合成一个区间；未明确币种或周期不擅自补全。小时工资仅在工时假设明确且政策允许时另存推算值，不能覆盖原值。

### 4. 验证、升级与停止

代码验证：schema 类型、证据确实存在、金额和日期合法性、关系引用完整性、来源冲突。证据存在只证明可追溯，不能证明解释正确，也不能检测所有遗漏。

下列情况升级到更强模型：任何拟自动 Block；复杂跨字段 OR/替代条件；否定或作用范围不清；原生字段与正文冲突；解析不完整；验证失败。首版不依赖便宜模型自称高置信来跳过这些情况。

强模型先独立读取完整 JD 和 schema，提交结果后才比较初次输出；不只看初次选中的句子。只比较影响事实和决策的差异，忽略字段顺序和同义表述。保留两份结果，不能以高阶模型最后一句话直接覆盖争议。

最多一次高阶复核；仍无法消解的差异进入 review_required。无供应商权限、超时、服务失败进入 pending，不制造分数或兜底放行。无源信息无法靠更贵模型补出来：完整文档确实没写薪资就保留 not_stated，不因此升级。

另抽查未触发升级的 present 和 not_stated 字段，检测便宜模型漏提取。相同模型的两次一致不是准确率证明，两个不同模型也可能共同出错。

### 5. 资格和评分分开

事实解析器不输出 priority 分数或 Block。独立决策器按候选人资料和已确认政策，对 AND/OR 树做 true / false / unknown 求值：OR 的一个分支满足即可；全部分支明确失败才失败；资料不足是 unknown。

必须条件明确不满足、证据无歧义并经复核后，才允许产生拟 Block。上线还必须通过下述验收。没有写某条件表示没有发现该限制，不等于候选人已证明满足，也不应凭空 Block。preferred 不进入硬门槛；高级标题只是信号时不能冒充学历事实。

解析内部记录 evaluated / pending，以及 review_required 附加标志；不新增用户可见的资格状态。产品状态严格映射为现有 Apply / Blocked / Pending，见下文修订合同。缺少薪资不影响资格完成。

Career Stage Fit 消费资格和阶段事实；Compensation 消费明确适用的薪资记录；Evidence Fit 将 JD 要求与候选人可证明的经历做映射；Company Strength 消费独立公司资料。Evidence Fit 未评估仍为 null，不生成 50。按现有政策允许的中性排序值与真实观察分数分开存储和展示；本设计不新增任何缺失分数策略。

## 验证与实施顺序

| 任务 | 独立结果与边界 | 验收证据 | 返回设计的条件 |
| --- | --- | --- | --- |
| 1. 固定合同 | 离线 schema、关系语义和用户确认案例；不调用生产 | Bachelor+YOE 的 OR、preferred、否定、缺薪资、毕业/开工日期均有明确期望 | 现有 schema 无法表达事实 |
| 2. 来源适配 | 只生成统一文档；保留原生字段和全文 | 官方 API、普通官网、动态页、失败页逐项读回 | 完整性不足以区分未写和未抓到 |
| 3. 两任务抽取 | 固定配置输出事实，不评分；依赖 1、2 | 固定样本的原文、输出、失败记录可逐条审阅 | 复杂关系只能靠猜或截断 |
| 4. 复核与决策 | 升级和三值逻辑；依赖 3 | 升级成功、争议、超时、未写、OR 各路径测试 | 复核仍无法区分事实与政策 |
| 5. 离线对比 | 同一批输入对比当前方案与新方案，不接生产 | 按字段、来源和难例分层的质量、覆盖率、成本、延迟报告 | 自动结果错误率或覆盖率不达预设目标 |
| 6. 影子运行 | 另行授权后只观察差异 | 人工复核拟 Block 和随机放行/缺失样本 | 来源漂移、漏提取或错误 Block |

现有 500 条双模型结果不能直接叫 gold。先独立裁定争议，并抽查一致样本；仍不明确的条目保留可接受结果集合。已看过并用于调 prompt 的案例是开发集，不能包装成新盲测。另建未参与调参、按公司及模板隔离的锁定测试集，尽量覆盖真实来源比例，同时单报 graduation、复杂 OR、preferred、缺薪资等难例。

报告至少包含：字段值和状态准确率、条件关系正确率、错误 Block 数、漏挡数、自动决策覆盖率、升级比例、review_required 比例、每条成本和 p50/p95 延迟。拒判不能从分母静默消失；模型间一致率单列，不叫准确率。

建议准入目标（待用户确认，不是已实现成绩）：每个核心字段语义正确率至少 98%；自动决策覆盖率至少 90%；错误 Block 比例的单侧 95% 置信上界不超过 1%，且已知回归案例全部通过。零错误时通常仍需约 300 个已人工确认可投岗位的独立判定，才能支撑该错误 Block 上界；500 条总量不必然满足各项分层验证。稀少字段必须补样，不用总体均值掩盖。

第一项可验证结果是：用已经裁定的难例证明合同能同时表达事实、未知和跨字段关系，而不是先重跑 500 条然后再改答案格式。只有合同稳定再比较抽取器。

## 后续优化，不是首版前置依赖

有充分人工裁定数据后，才能尝试将高频简单任务蒸馏为专用小模型，重用相同事实合同和独立测试集。只有达到同等质量且成本确实降低才替换。不能为了模仿 LinkedIn 而先建设知识图谱或训练平台。

本设计可用于离线 demo；生产启用条件和数值质量目标尚待批准。没有声称已解决当前 500 条数据的可靠性问题。

## Astra review 修订合同（优先于上文概述）

### R1. 硬门槛和事实严格分开

required 仅表示雇主措辞，不授予拦截权。资格决策器只消费政策白名单：地域、软件工作范围、明确的 senior/staff/principal 级别、强制学历/在读/毕业时间、要求 active/current clearance，以及明确超过 3 年的岗位经验门槛。其余技能、关键词、特定领域经验进入 Evidence Fit/提醒，不阻挡。

复杂 AND/OR 必须保留完整树。非硬门槛的分支在硬门槛投影中视为不构成限制，不能删除 OR 分支后把剩余分支变成唯一要求。实习返校未知遵循已有警告政策。未能确认比较口径的经验要求不能变成硬阻挡。

离线合同 demo 的资格执行范围限定为 degree、professional YOE、graduation、enrollment、seniority，其他类型保留为事实/提示或显式 unsupported；不宣称覆盖全部生产 gate。Demo YOE 使用 0–3 搜索政策可接受区间，而不是伪造用户实际拥有 3 年经历；不拿该搜索上限满足特殊技能经验的替代条件。

### R2. 用户可见状态映射

| 情况 | 产品状态 | 附加信息 |
| --- | --- | --- |
| 抓取不完整、模型失败、必须的升级尚未完成 | Pending | 仍可见；说明未完成原因 |
| 官方地点待查 | Pending | 仍可见；等待来源确认 |
| 评估完成，无明确硬阻挡，含歧义/实习返校未知 | Apply | review_required=true（如需），展示警告 |
| 明确硬冲突，但尚未经高阶复核 | Pending | 候选冲突，不展示成最终 Block |
| 明确硬冲突且两次完整解析支持相同实质结论 | Blocked | 精确证据和触发的政策类型 |
| 两次解析对硬冲突有未消解分歧 | Apply | review_required=true；不静默采纳后一份 |

“两次支持相同结论”需要比较导致冲突的相关事实及关系，而不是只比较两个 Block 字符串。解析不完整优先于任何 Block；完整文本未写薪资不触发升级，也不产生 Pending。禁止将 review_required 用作队列隐藏条件。

### R3. 联合时间、否定和三值逻辑

候选人方案是 December 2026 和 May 2027 两个毕业月份，不是中间任意日期。同一方案贯穿整棵条件树，且明确是否已获得学位、在读状态对应的判断日期。不能跨方案拼接不同叶节点的满足结果。未确认的未来 Master 不用于任何方案。

- AND：任一 false → false；全 true → true；否则 unknown。
- OR：任一 true → true；全 false → false；否则 unknown。
- 方案之间 OR：存在同一方案满足整体要求即可；一个方案为 unknown 时不能断言全部失败。
- No degree required 表示免除限制，不是候选人必须没有学位。
- Must not have graduated 表示候选人在指定时点尚未毕业；缺少时点保持 unknown。
- 日期保留精度。精确月按区间比较；只知道月份时不能制造某天毕业的事实。相交但不包含的候选日期区间产生 unknown。
- 不明数字下限的 Proven experience 保留 required + unknown numeric，不填 0，不直接 Block。

第一项合同 demo 使用显式、人工指定的候选人方案区间，而不推断真实用户未提供的履历。真实 JD 实跑仅验证事实抽取和路由，不伪造候选人资料来报告可投准确率。

### R4. 薪资消费和未决选择

相同来源或不同来源给出不同地区、级别、薪资组成的记录可以并存；只有同一适用范围内互斥的声明才是冲突。所有金额保留原始单位，禁止将 base 与 TC、不同币种或年度与小时区间直接合并。

来源未解决冲突，或金额/币种/周期/适用性未知时，不生成观察分数。多个合法美国范围并存时，合同返回 multiple_ranges，保留全部原文记录；本轮不选择最高值、最低值或平均值。选择规则属于新的评分政策，生产接入前需用户批准，但不阻塞事实抽取 demo。

### R5. 评估定义

开发难例允许使用已讨论样本。锁定验收集的每个实际计分答案都要独立人工裁定；模型一致项不可免检。不可确定条目保留 unknown/允许集合，不强迫单一真值。按公司及模板隔离，并按原生来源覆盖率分层；高重复相关样本不作为独立统计证据。

- 主字段指标按 JD×字段计数：状态、事实及实质关系均匹配才算正确；遗漏、额外虚构、错误作用范围均计错。报告所有计分条目的分母，拒判不从分母删除。
- 另外在真实含该字段的样本上报告事实召回，在预测事实中报告精确率，并单报 AND/OR、否定、preferred、日期及多薪资难例。缺失占比不得掩盖低召回。
- 错误 Block 率 = 真实无硬阻挡却被自动 Block / 全部真实无硬阻挡；漏挡率 = 真实有硬阻挡却进入 Apply / 全部真实有硬阻挡。
- 自动覆盖率 = 无 pending/review_required 的最终判断 / 全部输入。拒判另报；“歧义 Apply”不算已验证的自动判断。
- 正式准入规则在锁定测试前确认；上文 98%/90%/1% 仍是提议。漏挡界限、各难例最低样本量及预算也需先批准，不能看完测试再选阈值。本轮不进行生产准入声明。

开发 demo 全量审查选定难例，并对未升级的 present/not_stated 全量复核，避免小样本抽样遗漏；未来规模化时分别随机抽查至少 10%，按字段和来源单报。该比例是实验默认值，不是可靠性保证。发现系统性错误回开发集修正，已曝光的验收案例不再充当新盲测。

### R6. 本轮交付与边界

1. 设计补齐（本节），保留需要批准的薪资评分和生产准入选择。
2. 独立 scripts 合同模块和难例测试：机器可验证事实、显式条件树、证据校验、三值逻辑、状态映射、薪资记录选择状态；不 import 旧实验管线，不修改生产。
3. 离线 demo：先运行人工构造的合同反例，再对已有公开 JD 的完整存储正文做小规模两任务真实模型抽取，保存模型、输入、输出和失败记录。读取旧数据仅取已有 ID/正文/来源等必要字段。
4. 报告中分开合同测试通过、模型输出可解析、原文可追溯、人工语义复核；不把其中一项当作另一项的证据。不将一次小规模 demo 称为 500 条新盲测或端到端生产验证。

长文超限、供应商不支持 schema 或调用权限缺失时明确失败/未验证，不截断全文后宣称成功。高阶模型每项最多一次独立复核；调用失败仍保存可用的第一份输出，执行状态 pending。

解释器是演示用的政策投影，未实现完整履历、来源优先级及生产资格 gate。实跑采用 Sol 提取与 Terra 独立复核，并未证明 Terra 在此任务上更强。小样本全量复核，暂未验证选择性升级的成本收益。

最终发现及未解决项见 docs/jd-semantic-contract-demo-results.md：学历归一化、级别遗漏、记录级证据无法阻止共同推断薪资周期等问题仍需收敛。因此本轮交付完成的是设计修订、合同和有结果的开发 demo，不是生产 parser 或通过验收的准确率。
