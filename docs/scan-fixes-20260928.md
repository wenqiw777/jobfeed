## Items 3 and 4 result and verification

Run list/active GET routes no longer invoke write recovery. Recovery first checks for expired leases or genuinely orphaned empty claims as a WAL reader; only necessary recovery enters a writer transaction, where lease/owner conditions are re-read before mutation. Periodic recovery now runs with or without Redis, while Redis resume remains conditional on Redis being enabled.

Canonical Stage A and B claim loops now release the write transaction after each candidate, including skipped candidates. Input selection, revision/generation checks and the individual claim remain atomic inside that candidate transaction. A batch interrupted by an exception or cancellation releases already-committed claims it cannot return to the caller using the original revision and generation fences. No input-comparison representation or new integrity fields were introduced. The historical incident's precise lock holder remains unproven; this change removes the confirmed long-transaction structure without pretending historical attribution was captured.

Heartbeat renewal errors now record run ID, kind, generation, attempt, exception type, sanitized error and duration; fence rejection has a distinct event and is not retried. Disposition: preserve the existing twenty-attempt bounded store-exception retry strategy; do not broaden this fix into new cross-database transient-error classification. Lock contention is addressed through shorter transactions and read-only polling rather than increasing timeouts.

`jobfeed dev` keeps Vite HMR but defaults the API to stable/no reload. `--reload-api` explicitly opts into source reload and warns it interrupts scans. No process was manually restarted by this implementation agent.

RunManager now rejects new work during shutdown, waits for already-admitted setup (tracked separately from its caller task), cancels and awaits workers, and drains checkpoints. Setup cancellation also finalizes the lease and closes the source context. Source teardown and tracking cleanup run even if the finish hook raises. App lifespan awaits this shutdown before store closure. Service shutdown cancellation is recorded as `interrupted` with a shutdown message; user stop retains `user_stopped`.
